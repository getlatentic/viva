# v0.1 — someone else can run it

The first version another person can install, run, and judge. It is not the
version where the central claim pays off; that is stated below rather than
implied away.

## What it does

A long-lived agent that does ordinary work in a directory — reads and writes
files, searches a repository, runs commands — and, on request, decides for
itself what the work taught it and writes that down **outside the process**:
a note in `.vivarium/MEMORY.md`, a skill in `.vivarium/skills/`, a tool in
`.vivarium/tools/`. Plain files, editable and deletable by a person, and
callable by other agents over MCP.

```bash
vivarium do "the tests fail, fix it" --cwd ~/work/thing
vivarium do "summarise what changed" --retain
vivarium shell --cwd ~/work/thing
vivarium daemon start --background && vivarium attach
vivarium mcp --cwd ~/work/thing
./demo/retention
```

Sessions live in one long-lived process and outlive the terminal that started
them.

## What is proven

| | |
|---|---|
| 1,344 tests, green on a machine that had never seen the repository | `./bin/viva test` |
| the evolution lifecycle's safety properties: 13 TLC configs, 6 of them witnesses where the *violation* is the demonstration | `./spec/verify.sh` — needs Java and `tla2tools.jar`, and now says how to get them |
| retained capabilities are genuinely reached by later turns | `./experiments/kc6/preflight.sh` |

## What is parked

**The live-image door.** The agent can compile a replacement definition into
the running process, roll it back, and hand itself a tool mid-run. It works,
it is ledgered, it is specified in TLA+, and a real model used it.

It lost the experiment built to judge it. [Kill criterion
six](../../experiments/kc6/RESULTS.md) — 54 cells, 270 task-runs, $3.50 —
compared it against plain-text retention across six task families, under a
decision rule written before any run. It won **0 of 6**, at **1.9×** the cost
per solved task, and the arm-B control failed too. The door was genuinely used
(47 capabilities minted, 10 promoted), so this is not a null result from a
feature nobody exercised.

Parked by ratification, not deleted: the code, spec and tests all still stand,
`--capabilities on` still opens it, and revisiting it is
[#16](https://github.com/tosinamuda/vivarium/issues/16).

## What is unfinished

**Retention does not yet pay.** The [dogfood
study](../../experiments/dogfood/RESULTS.md) pre-registered four claims over
25 real recurring jobs. Three passed: retention happens (5 artifacts / 25
tasks), what it keeps is good (4 of 5 survived cold review), and it gets
reused (a tool written during one task was called five times by two later
ones). The fourth failed: **+8.2% tokens against a −20% threshold**, and split
— mechanical recurring work got cheaper, judgement work got dearer. That is
why `--retain` is opt-in.

A confound found afterwards, while building the demo, is recorded in the same
file: the task variants are not the same size, so the raw early-vs-late
comparison mixed data volume with learning. Corrected per kilobyte the winning
shape improves from −9% to −42%. The pre-registered verdict is left exactly as
it was written.

Also open:

- **the router** — reflection does not yet route by content shape, so a note
  and a tool are chosen by the model's judgement alone ([#1], [#6])
- **graduation** — nothing promotes a repeatedly-reused snippet into the
  registry on its own ([#8])
- **attachments** — retention follows `cwd`, so an agent pointed at several
  folders has several germlines and nowhere machine-level to share ([#14])
- **RECONCILE** — the co-effect ledger and compensation semantics ([#13])
- **the organism's own tools are not components** — they do not yet live under
  the proven evolution lifecycle ([#5])

## Fixed on the way here

The release sprint ran the software the way a stranger would, which found five
defects the suite could not:

- **`vivarium test` could not work on a clean machine.** ASDF resolves
  dependencies and never downloads them, so the one command a newcomer runs to
  check their install was the one that could not succeed.
- **`vivarium shell` did not start at all** — `Unknown &KEY argument:
  :EXTRA-TOOLS`, a hand-copied keyword list rotting for the third time. The
  copies are gone rather than corrected.
- **`daemon start --background` left nothing listening.** It detached the
  accept loop into a thread and then exited, taking thread and socket with it.
- **`daemon status` reported failures it had caused itself** — the liveness
  probe hung up on the greeting it had asked for.
- **the retention policy had no caller outside an experiment.** The organism's
  defining behaviour shipped switched off, with no switch. `--retain` is the
  switch, and `vivarium trust` is what lets a tool it wrote ever be called
  back.

## Verified

SBCL 2.6.7 / macOS ARM64. Install, suite, spec, preflight and the demo were
all run from a fresh clone of this tag, under a HOME with no Quicklisp and no
caches, with a provider key added exactly as the README describes.

On that run the organism wrote itself a tool, `usage-totals`, partway through
the demo and called it on a later task — the whole claim of this release,
happening on the run that verifies the tag.
